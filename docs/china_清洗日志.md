# 中国队列 · 清洗日志

> 由 `c3_clean.py` 生成。输入 `rc_china.csv`，输出 `china_analysis.csv`。

输入规模：**211,833 行 × 25 列**

## 1. 派生变量

- `male` = gender==1。**为什么要转**：原始 1=男 2=女，直接进模型会被当成连续变量，解读成「性别每增加 1 单位风险变化」——毫无意义
- `age_grp`：20-29 / 30-39 / 40-49 / 50-59 / 60-69 / 70+，`right=False`
- `bmi_cat`：按 **china** 切点 [18.5, 24.0, 28.0]，**`right=False` 是关键**——默认左开右闭会把 BMI 正好 24.0 的人分进「正常」，而临床标准是 ≥24 即超重
- `log_tg` = log(1+tg)。原始 tg 右偏（少数人 >10，多数人 ~1），取对数后分布对称，进模型残差更稳。用 `log1p` 而不是 `log` 是为了防 0 值
- `site_small`：标记样本量 <500 的站点 [16, 0]，共 308 人。**只标记不删除**——是否合并要等建模时看分层 Cox 的实际表现再定

## 3. 缺失检查（本步最关键的结论）

| 变量集 | 用途 | 完整病例 | 占比 | 删掉 |
|---|---|---|---|---|
| M1/M2 | 主模型 | 211,833 | 100.00% | 0 |
| M3 | 敏感性 | 205,291 | 96.91% | 6,542 |
| M4 | 敏感性 | 205,291 | 96.91% | 6,542 |

**结论：主模型（M2）用的 6 个变量 0% 缺失，一个人都不用删。**

这是审计阶段没想到的——审计时看到 `smoking` 缺 71.6%、`hdl` 缺 44.6%，以为这个数据集缺失很严重。但那几个变量**根本不进主模型**。

所以：**不做多重插补，用完整病例分析（complete case）**。

**但要证明「删掉的人不是特殊人群」**——M3 会删 3.09%，必须看这 3% 长什么样：

```
                    age     bmi    fpg     tg  followup_years  dm_censor
被删（缺 tg/tc/alt）  39.325  23.309  4.906  1.473           2.908      0.016
保留               42.186  23.233  4.916  1.338           3.129      0.020
```

年龄差 3 岁（39.3 vs 42.2），BMI 和发病率几乎无差。年龄差异来自 tg/tc 检查在部分站点/年份未开展，那些人群偏年轻。
**判定：差异存在但不影响结论，M3 结果需在报告里注明「完整病例分析，n=205,291」。**

## 4. 这一步有意不做的事

| 没做什么 | 为什么不做 |
|---|---|
| 没删 `/site 0` 的 61 人 | 虽然 0 发病，但删数据要有依据。标记为 `site_small`，建模时看分层 Cox 怎么处理 |
| 没截断 tg / alt 的极端值 | 极端值可能是真实的重度患者，不是录入错误。截断会人为减小方差，属于篡改。做敏感性分析（1%/99% winsorize）对比 |
| 没给 `smoking` 填任何值 | 缺失 71.6% 且是站点级结构性缺失，填值等于编数据。主模型不用它 |
| 没把 `dm_incident` 当结局 | 审计已确认它只标了 31% 的发病者 |
